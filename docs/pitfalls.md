# ハマりどころ全集（pitfalls）

AIに漫画を描かせるパイプラインで、**実際に踏んだ罠**の記録です。
全部、原稿を落としたか、絵が壊れたか、時間を溶かしたやつです。
読むだけで数日ぶん節約できると思います。

---

## 【罠1】🚨 依頼文の先頭に「成果物強制の3行」を置かないと、宣言だけで終わる

**症状**：AIが「制作開始っ✨」「いま生成本体が走ってるよ」と**元気に宣言するだけで、画像生成ツールを呼ばずにターンが終わる**。文面を変えて3回投げても同じ。利用上限とは無関係（同じ夜に別の依頼では22枚生成できていた）。

**原因**：ログを見ると、画像生成スキルのドキュメントを延々読み込んだところで力尽きている。前置きが長いと、生成に到達する前にターンが終わる。

**対策**：依頼文の**いちばん上**にこれを置く。

```
🚨 いま画像生成ツールを実際に呼び出して、<対象>の画像を1枚生成してほしい。
   計画や宣言だけで終わらせず、生成したPNGの絶対パスを最後に1行で出力してほしい。
   ドキュメントは読まなくていい。
```

効くのは3点セットだからです：
1. **「いまツールを呼べ」** — 実行タイミングを今と指定する
2. **「PNGの絶対パスを1行で出力」** — 出力できること自体が生成した証明になる（宣言だけで終われなくなる）
3. **「ドキュメントは読まなくていい」** — 探索作業に逃げさせない

⚠️ **長いYAMLを渡す依頼でも起きます**。「短い依頼のときだけ」ではありません。
⚠️ **`resume` で続きを頼むときも毎回付けてください**。2ページ目以降でも起きます。

`forge.sh` は全ページの依頼文に自動で挿入しています。

**検品**：ログに `generated_images/<UUID>/...png` の行があれば成功。宣言文だけなら失敗なので再依頼。

## 【罠2】`-i` の後にプロンプトを書くと、プロンプトが画像扱いされる

**症状**：`codex exec -i a.png -i b.png "プロンプト"` が
`No prompt provided via stdin.` で落ちる。

**原因**：`-i, --image <FILE>...` の `...` が複数値を貪欲に食うので、プロンプト文字列まで画像パスとして解釈される。

**対策**：**プロンプトは必ず stdin（heredoc）で渡す**。

```bash
cat <<'PROMPT' | codex exec -i ref1.png -i ref2.png
（ここに依頼文）
PROMPT
```

変数展開が必要なら `<<PROMPT`（クォート無し）にします。

## 【罠3】`resume --last` は使わない。セッションIDで名指しする

**症状**：漫画のページを焼いている最中に、別の画像生成（サムネ、ヘッダー画像など）を並行実行したら、**別作品のキャラや画風が混入した**。

**原因**：`codex exec resume --last` は「**最後に使った codex セッション**」を指す。プロセス単位ではなく、同じPCの codex 全体で共有される。別のエージェントや別の作品が途中で codex を使うと、続きを頼んだつもりが**その別の会話**を掴む。

**対策**：**page1 のログに出る `session id: <UUID>` を控えて、page2 以降は `codex exec resume <UUID>` で名指しする**。
```bash
SESSION_ID=$(grep -oiE 'session id:[[:space:]]*[0-9a-f-]{36}' forge.log | head -1 | grep -oiE '[0-9a-f-]{36}')
cat page2_prompt.txt | codex exec resume --skip-git-repo-check "$SESSION_ID" -
```
- これなら**他の codex 呼び出しと並走しても混ざらない**（`forge.sh` はこの方式です）
- `session id` は `~/.codex/generated_images/<UUID>/` のフォルダ名と同じなので、回収にも使えます（【罠7】）
- 新しい codex では `--last` が「いまのフォルダで最後の会話」に絞られることもありますが、**それに頼らず ID で指す**のが確実です

## 【罠4】1作品＝1セッション。混ぜると前の画風を引きずる

**症状**：油彩の作品を焼いた直後に、同じセッションで「ちぎり絵」を頼んだら、**厚塗りのままのちぎり絵**が出てきた。

**対策**：
| 単位 | やりかた |
|---|---|
| **作品が変わったら** | 必ず `codex exec` で**新規セッション** |
| **同じ作品のページ間** | page1 の `session id` を `resume <ID>` で名指しして会話を継続（キャラデザ・背景の一貫性のため。【罠3】） |
| **描き直し（リテイク）** | **新規セッション**。画風を変えるなら依頼文に「さっきまでの画材は忘れてほしい」も添える |

`forge.sh` はこの構造（page1=新規、page2以降=session id 指定の resume）で実装しています。

## 【罠5】ページ数 ≠ 画像枚数。作画AIが勝手にリテイクする

**症状**：2ページ頼んだのに**3枚**生成されていた。ページ順に並べたら1ページ目が重複していた。

**原因**：作画AIが自分で「ここ弱いな」と判断して**自主的に描き直す**ことがある（頼んでいないのに）。改良版のほうが良い場合も多い。

**対策**：
- 「N枚生成されたから page1..N」という前提を置かない
- `forge.sh` は**各ページの依頼中に増えたPNG**を `out/<作品名>/takes.tsv` に記録します。`collect.sh` はそれを見て、**そのページで最後に描かれた1枚**を `pageN.png` に採用し、先に描かれた分は `rejected/pageN-takeK.png` に分けます
  - 実例：NDM v10.5 のページ指示（フキダシ外の文字は描き直し対象）にしてから、サンプル2ページで「指定外の看板文字がある」「背景が指定より細かい」と両ページとも自主リテイクされた
- それでも**検品で右上のページ番号（例「3/10」）は必ず見る**（あるページの依頼中に前のページを描き直す、などは記録上そのページの絵として扱われるため）
- `takes.tsv` 無しで手動回収した場合（`collect.sh --log ... --out ...`）は従来どおり生成順に並べ、枚数不一致なら警告を出します

## 【罠6】🎯 bbox は「目安」。作画AIは構図を優先してコマ位置を動かす

これがいちばん大事な仕様理解です。

**症状**：ネームに書いた座標（bbox）どおりのコマ枠を画面に重ねたら、**実際の原稿とズレていた**。ページによって平均50〜200px、最大378pxもズレていた。

**原因**：**これは仕様どおりの正しい挙動**です。OMAY の layout_spec にこう書いてあります。

> bbox をピクセル単位で厳密に再現しようとしてはならない。bbox が伝えるのは
> 「コマ内のどのゾーンに・どのくらいの大きさで」であり、構図の自然さ・
> キャラのポーズ・パースの整合が bbox の厳密な再現より優先される。

つまり **bbox は「意図の伝達」であって「レイアウトの確定」ではない**。
作画AIは絵として自然になるようにコマを調整します。それで絵は良くなります。

**帰結（重要）**：
- ✅ **ネームを書く目的**には bbox で十分。読み順とゾーンが伝われば漫画は成立する
- ❌ **完成原稿の座標が必要な用途**（コマを切り抜く／枠に何かを重ねる／コマ単位でアニメーションさせる）では **bbox を信じてはいけない**。**完成原稿から実測する**必要がある

実測が必要になったら：
1. 白いガター（コマ間の余白）で再帰的にXYカットして枠を検出する — これで単純なグリッドの8割は自動で取れます
2. 斜めコマ・変則グリッド・1コマだけのページは自動検出が外れるので、**目視で採寸する**
3. さらに、**作画AIがコマの並び順を入れ替えることもある**（左右逆・洋順グリッドになる等）。セリフを手がかりに対応付けてください

## 【罠7】並列実行時は「自分のUUID」から回収する

**症状**：複数の生成を並行したら、別の生成物を回収していた。

**原因**：`~/.codex/generated_images/` の**最新フォルダを取る**方式は、並行実行で混ざる。

**対策**：**自分の実行ログに出てきたUUID**のフォルダから取る。この UUID は codex の `session id` と同じです。`collect.sh` がこれをやっています（`--session <UUID>` でも指定できます）。

## 【罠8】文字は「作画と同時」に描かせる。後から写植しない

**症状**：文字なしの原稿を作って後からプログラムで写植したら、**フキダシと文字の整合が破綻**した（はみ出し・改行位置・縦書きの列送り）。

**対策**：**セリフ・フキダシ・タイトル・ページ番号を作画と同時に画像生成AIに描かせる**。文字化けやはみ出しがあったら、後加工せず**そのページだけ再生成**する。

これは OMAY の style_notes に明記されています。

---

## 【罠9】キャラの服装・季節がリファレンス次第で矛盾する

**症状**：35℃の設定で、扇風機とかき氷を描いた画面の中で、**キャラだけ長袖の上着**を着ていた。

**原因**：リファレンス画像に通年版（長袖）の立ち絵を使っていた。ワークフローが複数あると、片方だけ季節チェックが漏れる。

**対策**：
- 季節の記号（かき氷・こたつ・雪・打ち水）を描くときは、**服装がそれと矛盾していないか生成後に必ず見る**
- 衣装差分を用意して、**季節ごとにリファレンスを切り替える**運用にする（`docs/characters.md` 参照）

## 【罠10】タイムアウトは長めに取る

複数ページを1枚ずつ順に生成するので、**10ページで10〜20分**かかることがあります。
- 1ページあたり 60〜120 秒が目安
- 自動化するなら timeout は **ページ数 × 120秒 + 余裕**
- `forge.sh` は session id で続きを頼むので、待つ間に他の codex を使っても混ざりません（【罠3】）

---

## 【罠11】git の外のフォルダで codex が黙って終わる

**症状**：作業用の空フォルダから `codex exec` を呼んだら、**1行も出力せずに終了コード 0** で終わった。

**原因**：`codex exec` は既定で「git リポジトリの中」でしか動かない。外だと拒否して終わるが、スクリプトからだと失敗に気づきにくい。

**対策**：`codex exec` にも `codex exec resume` にも **`--skip-git-repo-check`** を付ける。`forge.sh` は付けています。あわせて、**終了コード 0 を成功と判断しない**（ログに `session id` と `generated_images/<UUID>/...png` が出ているかを見る）。

## 検品チェックリスト

焼き上がったら、全ページを実際に**目で見て**ください。

- [ ] ページ欠けがない（ヘッダーの「N/M」を確認）
- [ ] セリフが読める（大きな文字化けがないか）
- [ ] キャラの取り違えがない
- [ ] キャラの衣装・髪型がページ間で一貫している
- [ ] 季節・時間帯と服装・背景が矛盾していない（【罠9】）
- [ ] フキダシの尻尾が話者を指している（caption・handwritten・`offscreen: true` は尻尾なし）
- [ ] 意図した無音コマ（フキダシゼロ）が絵だけで成立している

軽微な文字のゆらぎは生成の性質として許容し、気になるページだけ再生成するのが現実的です。
